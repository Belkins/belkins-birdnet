# The Popup Budget — a constitutional constraint on the bird dossier

*Adopted 2026-07-02. This is the §8e ruling from the repaint swarm, written down so it cannot be
re-litigated one "calm little control" at a time.*

The rich popup (the bird dossier on `/collage`) is **museum zone**. Its restraint is the product's
signal of taste; every specialist pass that touches it independently proposes "just one" addition,
and by accretion that is how museum walls become dashboards. So the budget is explicit:

## The zones and their caps

| Zone | Cap | Currently holding |
|---|---|---|
| **Plate** (the artwork area) | ≤ 2 controls; the pose toggle counts as ONE group | pose toggle |
| **Footer action zone** (write-actions that change state or spend money) | **HARD CAP: 2** | `repaint ↺` · `save plate ↓` |
| Navigation links (read-only, outbound) | not counted as controls | `wiki ↗` · `ebird ↗` |
| **Companion slot** (v3 doctrine: ≤1 zero-control, silent-when-unbacked line) | 1 — **still UNSPENT** | — |

## The rules

1. **The control budget is CLOSED.** Adding any control to the popup requires founder sign-off
   AND the removal of an existing control. There is no third footer action.
2. A **control** is anything that writes, spends, or triggers work (repaint, save). A **link**
   navigates. A **caption** informs. Only controls count against the caps.
3. The companion slot stays reserved for a zero-control element (e.g. a Field Note line or the
   local-rarity refinement) — the repaint button did NOT spend it.
4. State messages reuse the slot of the control that caused them (the repaint button *transforms*
   through its lifecycle — confirm, `painting…`, `still drying`, the parked caption — it never
   adds elements).
5. Pre-agreed tripwire (from the unlock-swarm): if the popup ever shows more than the capped
   controls, stop all frame-zone feature work until it is back under budget.
